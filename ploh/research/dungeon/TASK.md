# 던전 배경 아트 디렉션 조사: 던전밥과 애니·만화 레퍼런스

PLOH(로드 오브 히어로즈 스핀오프 시제품)의 던전 배경을 다시 잡기 위한 조사다. 애니메이션과 만화, 그중에서도 **던전밥(ダンジョン飯, Delicious in Dungeon)**이 던전을 어떻게 그리는지 실제 장면을 근거로 모으고, 그것을 **우리 카메라와 우리 생성기**에 맞는 아트 디렉션과 구현 목록으로 옮긴다. 결과물은 내부 제작용이다.

이 폴더(`ploh/research/dungeon/`)에서 작업한다. 문서는 모두 **한국어**로 쓴다(고유명사·기술 용어는 원어 병기 가능).

## 0. 반드시 지킬 것

1. **지어내지 않는다.** 직접 열어 본 페이지, 직접 받은 영상 구간, 직접 본 이미지만 근거로 쓴다. 에피소드 번호, 타임스탬프, 챕터, 페이지를 모르면 "미확인"이라고 적는다. 그럴듯한 숫자로 채우지 않는다.
2. 각 레퍼런스에 **확인 상태**를 붙인다: `[직접 확인]`(영상 구간·이미지를 직접 받아 보고 내용이 맞음을 확인) / `[문서 확인]`(위키·공식 페이지 글로만 확인) / `[미확인]`.
3. 레퍼런스 이미지는 `refs/` 에만 저장한다. `refs/.gitignore` 는 이미 있으니 **지우거나 바꾸지 않는다**. 저작물이므로 커밋·게시하지 않는다.
4. **`ploh/game/` 아래는 절대 수정하지 않는다**(읽기만 가능). 다른 사람이 동시에 게임 코드를 고치고 있다.
5. git 커밋하지 않는다. AI 이미지 생성은 하지 않는다(콘셉트 그림은 따로 만든다).
6. 영상은 전체를 받지 말고 `yt-dlp --download-sections "*MM:SS-MM:SS"` 로 필요한 구간만 받는다. 받은 영상은 `refs/video/` 에 두고 작업이 끝나면 지워도 된다. 프레임은 ffmpeg로 뽑아 JPG(긴 변 1280px 이하)로 저장한다.

## 1. 우리 게임(읽고 시작할 것)

- 세로 화면(720×1280) 한 손 조작 아이소메트릭 3D 액션 RPG. Godot 4.4 **GL Compatibility** 렌더러, 웹 빌드, **저사양 아이폰 60fps**가 목표다. 그래픽보다 애니메이션·타이밍이 우선이므로 배경은 **싸게** 그려야 한다.
- 카메라: 방향(yaw) 45° 고정, 내려다보는 각(pitch) 50°, 영웅에서 약 8.2m(보스 방 10.2m), 세로 화면에서 가로 시야각 50°. 초점 거리에서 화면 가로가 약 7.6m라 **1m ≈ 94px**(720px 폭 기준). 캐릭터는 화면에서 약 80–150px, 방(지름 10–14m)이 화면을 거의 채운다.
- 현재 모습: `current/*.png` 를 반드시 보라(같은 생성기로 찍은 실제 화면, 영웅이 검게 나온 것은 작업 중인 셰이더 탓이니 무시).
  - 문제: 바닥 자갈이 고르게 반복돼 타일처럼 보인다. 벽이 같은 돌쌓기 띠로 방을 둘러싼 "울타리"처럼 보인다. 벽 윗면은 어두운 회색 판이고 그 밖은 검보라 허공이다. KayKit 통·상자가 장난감 같은 복숭앗빛이다. 사람이 살았던 흔적과 이야기가 없다.
- 생성기: `ploh/game/scripts/dungeon.gd` (꼭 읽을 것)
  - 노이즈로 일그러진 타원 방 5개를 휘어진 복도로 잇는 거리장(SDF), 0.5m 격자 marching squares로 벽·바닥을 만든다.
  - 벽 높이 3.4m, 카메라 쪽 벽은 1.8m로 낮추고 영웅을 가리는 부분은 디더링으로 녹인다(`shaders/wall.gdshader`). 벽 윗면 두께 0.8m.
  - 지형 높낮이(경사로가 있는 단 0.45–0.8m, 잔해 둔덕), 보스 방 가운데 제단.
  - 얕은 물웅덩이(`shaders/water.gdshader`, 모바일은 `water_lite.gdshader`), 깜빡이는 횃불(OmniLight, 범위 10m, 색 (1.0, 0.62, 0.32), 7m 이상 간격, 모바일은 16m 밖에서 끔), 부서지는 통·상자, MultiMesh 잔돌.
  - 재질: `ploh/game/assets/textures/README.md` (gpt-image로 만든 seamless 1024² 텍스처: floor_stone, floor_mud, wall_stone, moss_grime, water_normal). 바닥 셰이더 `shaders/floor.gdshader`, 벽 셰이더 `shaders/wall.gdshader`.
  - 조명 환경: `ploh/game/scripts/game.gd` 의 `_build_env()` (배경색 (0.03,0.03,0.05), 앰비언트 (0.42,0.44,0.6)×0.62, Filmic, 노출 1.1, 글로우는 PC만, 안개 밀도 0.02, 달빛 DirectionalLight (0.75,0.8,1.0)×0.7, 모바일은 그림자 끔).
  - 가진 소품(KayKit Dungeon CC0, `ploh/game/assets/kaykit/dungeon/`, 채도 낮춘 팔레트 아틀라스 하나를 공유): banner_red, barrel_large, barrel_small, box_large, box_small, candle_triple, chest_gold, column, crates_stacked, floor_tile_large, floor_tile_large_rocks, floor_tile_small, keg, pillar, pillar_decorated, rubble_large, torch_mounted, wall, wall_broken, wall_corner, wall_cracked, wall_doorway, wall_half. 해골 적 팩(`assets/kaykit/skeletons/`)도 있다.
- 모바일 비용 상식(Godot 4.4 Compatibility): 메시 하나당 OmniLight 8개 + SpotLight 8개까지(그래서 바닥·벽을 8m 덩어리로 나눔). 그림자 있는 조명은 추가 패스라 모바일에서는 쓰지 않는다. 화면 공간 반사(SSR)·SSAO·볼류메트릭 안개는 없다. 반투명 겹침(overdraw)과 텍스처 샘플 수, 그리기 호출 수가 주된 비용이다.
- 세계관: `ploh/research/world.md`. 유럽풍 판타지. 적은 **갈루스 제국군**(마도공학·마도증기기관, 날개 편 독수리 문장, 남색·금색·진홍 제복, 회색 군모, 드론, 마도병기 '타이탄')이다. `ploh/design/enemies/ROSTER.md` 도 읽어라.
- **색 예약**: 적 공격 예고가 바닥에 **빨강·금색·시안·주황·보라**로 그려진다(ROSTER.md 1장). 배경 바닥과 큰 면에는 이 색들을 채도 높게 쓰면 안 된다. 횃불의 주황 빛은 괜찮지만 바닥 색 자체가 주황·금색으로 물들면 예고가 묻힌다.

## 2. 사용자의 방향

- 던전밥과 다른 애니·만화를 던전 배경의 레퍼런스로 삼고, **제대로** 할 것.
- 던전은 **사실적이고 사람이 살았던(lived-in)** 느낌. 타일 같지 않게. **너무 어둡지 않게.**
- 부서지는 소품, 얕은 웅덩이 반사, 횃불은 유지.
- 그래픽은 애니메이션·타이밍보다 뒤이므로 렌더 비용이 싸야 한다.

## 3. 조사할 것

### 3.1 던전밥 (필수, 가장 깊게)
애니(TRIGGER, 2024, 1기 24화, 2기 제작 발표)와 원작 만화(구이 료코, 14권 97화)를 모두 본다. 다음 주제마다 **구체적인 장면**을 찾아라.
- 황금의 나라(황금향)와 그 지하에 잠긴 성·성하 마을. 던전이 어떻게 생겨났는지에 대한 작중 설정.
- 층별 구성: 층마다 어떤 공간(묘지·숲·성채·수몰 구역·성하 마을 등)인지, 층마다 색과 빛이 어떻게 달라지는지. 위키의 층 목록 페이지를 근거로 하고, 각 층이 나오는 화·챕터를 적는다.
- 살아 있는 던전: 던전이 스스로 복구되고 변한다는 설정, 미믹·덫·'청소부' 같은 던전 생태.
- 재배·생태: 센시의 골렘 밭, 이끼·버섯·식물·물고기 같은 던전 안 먹거리, 그것이 화면에 어떻게 보이는지.
- 모험가의 흔적: 야영지와 요리 장면(냄비, 모닥불, 침낭, 짐), 다른 파티의 흔적, 죽은 모험가의 유해와 장비, 게시물·표식·밧줄·사다리 등.
- 빛: 던전 안 광원(횃불, 랜턴, 마법 빛, 발광 생물, 위에서 새는 빛 등)과 그로 인해 "어두운 던전인데도 잘 보이는" 이유.
- 공식 PV·예고편·논크레딧 영상(넷플릭스, TOHO animation, KADOKAWA 등 공식 채널), 공식 사이트, 미술 설정·배경 미술 관련 인터뷰(미술감독, 배경 스튜디오)를 우선 찾는다. 배경 미술 담당이나 미술 설정에 대한 공식 인터뷰가 있으면 핵심 문장을 인용하고 URL을 남긴다.

### 3.2 다른 작품 (최소 3편, 관련도 순으로 고르고 고른 이유를 적는다)
후보(이 밖의 작품도 좋다): 장송의 프리렌(1급 마법사 시험 2차의 던전 '零落の王墓' 등), 메이드 인 어비스(층 구조, 유물, 규모감), 천공의 성 라퓨타(뿌리에 삼켜진 폐허), 바람계곡의 나우시카(부해 아래 지하 숲의 빛), 베르세르크(성채·지하 감옥·고문실의 석조), 드래곤 퀘스트 계열 JRPG 던전 아트, 무직전생 전이 미궁, 고블린 슬레이어의 동굴 등.
또한 **우리 카메라와 거의 같은 시점**의 게임(예: Hades, Diablo IV / Diablo II: Resurrected, Torchlight 등)을 1–2편 "번역용 레퍼런스"로 넣는다. 애니 배경을 위에서 내려다본 3D로 옮길 때 무엇이 남고 무엇이 사라지는지 보여 주기 위해서다. 공식 스크린샷·공식 영상만 쓴다.

### 3.3 레퍼런스마다 적을 것
- 작품, 화·챕터, 타임스탬프 또는 페이지, 출처 URL(직접 연 것), 저장한 파일 이름(`refs/` 상대 경로), 확인 상태
- **가져올 것**을 항목별로: 건축(구조·스케일), 재질, 광원, 색온도, 소품(set dressing), 생활 흔적과 이야기, 스케일 단서
- 이 장면에서 **가져오지 말 것**(우리 카메라·비용으로는 안 되는 것)

### 4.2 `refs/` 레퍼런스 이미지
- 파일 이름: `<작품약칭>_<화 또는 챕터>_<MMmSSs 또는 p쪽>_<주제>.jpg` 예: `meshi_e03_12m40s_golem_farm.jpg`, `frieren_e21_05m10s_tomb_hall.jpg`. 모르는 부분은 `unk`.
- 이미지 하나하나를 직접 열어 보고 설명과 맞는지 확인한다. 맞지 않으면 지운다.
- 장면마다 대표 프레임에서 **색을 뽑아라**(Python+Pillow 양자화나 ffmpeg palettegen 등). 결과는 `refs/palettes.md`(커밋 안 됨)에 남기고, ART_DIRECTION.md의 팔레트 근거로 쓴다.

### 4.3 `ART_DIRECTION.md` — 우리 카메라 각도에서의 방향
1. **공간 개념**: 한 문장 콘셉트(예: "동굴에 삼켜진 갈루스 이전 왕국의 성"). 던전밥처럼 깊이에 따라 바뀌는 구역 3–4개와, 우리 생성기의 방 5개(1–4번 일반, 5번 보스)와 복도를 어디에 배정할지. 방 종류(입구·창고·야영지·수몰 구역·예배당·보스 방 등)마다 어떻게 보이는지.
2. **팔레트**: 앰비언트, 키 라이트(달빛 역할), 횃불, 보조 광원, 강조색의 hex 값. 바닥·벽·벽 윗면의 기준 명도. 레퍼런스에서 뽑은 색을 근거로 들고, 1장의 '색 예약'과 겹치지 않는지 확인한다. Godot에 그대로 넣을 수 있게 `Color(r, g, b)` 값도 함께 적는다.
3. **재질 목록**: 바닥, 벽, 벽 윗면, 잔해, 나무, 금속, 이끼, 물. 각각 색, 거칠기, 미터당 반복 크기, 어떤 텍스처(기존/신규)로 만들지.
4. **조명 계획**: 광원 종류·색·범위·감쇠·배치 간격. "어둡지 않으면서 분위기 있는" 이유를 수치로(예: 바닥 평균 명도 목표, 앰비언트와 횃불 빛의 비율). 모바일에서 메시당 조명 8개 제한을 지키는 방법.
5. **방 종류별 소품 배치**: 던전밥 정신의 이야기 소품(냄비 얹은 모닥불, 침낭, 게시물, 앞선 모험가의 뼈와 장비, 버섯·이끼 군락, 뿌리, 쇠사슬, 무너진 석조, 갈루스 군 잔해 등). 소품마다 크기(m), 화면에서의 크기(px), 기존 KayKit으로 되는지 신규가 필요한지.
6. **피할 것**: 타일 반복, 평평한 조명, 노이즈 같은 자잘한 디테일, 예고 색과 겹치는 바닥, 과한 채도, 검은 허공 등. 각각 왜 나쁜지와 대안.
7. 우리 카메라(위에서 50°)에서 **벽 윗면과 방 밖 허공**을 어떻게 처리할지(지금은 검보라 허공이 화면 위쪽을 차지한다).

### 4.4 `TASKS.md` — 우선순위 구현 목록
- 항목마다: 우선순위(P0/P1/P2), 무엇을, 왜(기대 효과), 종류(텍스처 / 소품 메시 / 셰이더·조명 / 배치), 손댈 곳(`dungeon.gd` 의 함수 이름, 셰이더 파일, `game.gd` `_build_env()`), **모바일 비용**(그리기 호출, 텍스처 메모리, 픽셀당 텍스처 샘플·조명 수, 반투명 겹침), 필요한 자산.
- 텍스처 항목: gpt-image seamless, 2의 거듭제곱 크기, 어떤 채널(albedo/normal/roughness/alpha, 채널 묶기 가능 여부), 프롬프트 초안.
- 소품 항목: 기존 KayKit 팔레트 소품으로 되는지(어떤 모델을 어떻게 조합·변형), 아니면 새 메시가 필요한지(대략 폴리곤 수, 팔레트 아틀라스 공유 여부).
- 비용이 큰 것은 큰 것이라고 솔직하게 적는다.
