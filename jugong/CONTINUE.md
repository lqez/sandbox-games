# 현재 상태와 다음 작업

기록일: 2026-09-08

## 대화에서 확정된 내용

사용자는 사진 6장을 바탕으로 10층 주공아파트 STL을 요청했다. 첫 모델에 대해 정확하지 않다고 지적하고, 재개발 전 둔촌주공 타워형임을 명시했다. 특히 전후·측면 구분, 더 돌출된 발코니와 명확한 창틀을 요구했다. 이후 출입구가 양쪽에 있었다고 보완했다. 발코니 외부 섀시와 에어컨 거치대는 기본 요소가 아니므로 기본 숨김 및 별도 show/hide를 요구했다.

이 요구에 맞춰 정림건축의 25T형 자료와 사용자 사진을 대조한 두 번째 모델을 만들었다. 사용자의 최신 요청은 “이걸 codex에서 이어가고 싶은데”이며, 이 폴더가 그 이어가기 자료다. 두 번째 모델의 정확도에 대한 사용자 최종 승인은 아직 없다.

## 완료한 작업

- 전면/후면/좌측/우측을 나눈 형상, 10층, 양측 출입구, 돌출 발코니와 원래 창호를 구현했다.
- 외부 섀시와 AC 거치대가 모두 없는 기본형과 두 독립 옵션의 조합을 STL 4개로 제공했다.
- HTML에 4개의 융합 STL을 내장하여 옵션 변경과 현재 구성 다운로드를 구현했다.
- STL 4종의 닫힌 메시, 양의 부피, 면 방향 및 단일 연결체를 검증했다.
- HTML의 내장 STL을 풀어서 원본 STL과 바이트 일치를 검증했다. 이전 뷰어 JavaScript는 구문 검사를 통과했다.
- 실제 기본 STL을 렌더링한 전후·측면 및 입체 미리보기를 만들었다.
- 사진에서 확인된 302·324·420동 선택과 안전한 직접 입력, 옥상 코어 명판을 추가했다.
- 10층 × A~D 라인의 안정적인 40세대 키와 외벽 방향을 정의했다. 화면 호수는 자료 미확정 때문에 모두 추정으로 표시한다.
- 세대별 외부 섀시 `없음/부분/전체`, 에어컨 `없음/거치대만/실외기 포함`을 독립 선택하고 전체·층·라인 일괄 적용할 수 있다.
- 기본 메시와 160개 주소 레이어를 뷰어에서 조립하며 현재 선택만 3MF로 다운로드한다. URL과 JSON으로 구성을 재현한다.
- 같은 JSON을 생성기에 전달해 단일 연결 STL을 만들 수 있고 대표 네 구성의 닫힘·연결성을 검증했다.
- 기본형과 현재 세대 구성에 정확히 네 `basematerials` 슬롯과 삼각형별 재료 참조를 갖는 3MF 출력을 추가했다. 팔레트 색은 네 슬롯 안에서 교체 가능하다.
- 원래 창호·난간, 유리·개구부, 옥상·후대 부착물을 재료별로 태깅하고 외벽 보수 흔적은 1:200에서 읽히는 넓은 0.4 mm relief로 제한했다.

## 아직 확인할 사항

1. 동별 실제 층·호수표 또는 건축물대장을 확보하면 추정 호수와 A~D 키의 대응을 검토한다. 내부 키는 저장 구성 호환을 위해 바꾸지 않는다.
2. 사용자 사진과 현재 각 방향 미리보기를 나란히 비교한다. 큰 형태가 맞는지 먼저 보고, 발코니 측벽·난간·창짝 분할·지붕 높이 등 차이를 근거와 함께 정리한다.
3. 옥상 기계실, 명판 실제 위치, 지면 높이와 후대 실외기 외형을 자료에서 더 확인한다. 현재 명판·실외기 세부 형상은 구성 확인용 추정이다.
4. 실제 프린터에서 4색 3MF를 시험 출력하고 장비별 extruder/AMS 슬롯 매핑을 저장한다. 현재 검증은 메시·패키지 구조·재료 참조와 Bambu Studio CLI 실행 환경 확인까지다.
5. 형상을 수정했다면 STL 4종, 세대 레이어, 뷰어, 미리보기와 검증 결과를 함께 갱신한다.

## 기술적 연결점

`build_layers()`에서 구조체·개구부와 세대별 선택 부재를 만들고 `build_base()`에서 기본형과 40세대 딕셔너리를 반환한다. `configuration_parts()`가 schemaVersion 1 JSON을 같은 레이어로 해석하고 `export_checked()`가 하나의 연결 솔리드를 내보낸다. `--all-variants`는 기존 4 STL과 `work/configurator`의 160개 뷰어 레이어를 함께 만든다.

뷰어 상태는 `schemaVersion`, `dong`, 40개 `households[id].sash/ac`으로 구성된다. gzip/base64로 압축한 기본·주소 레이어를 `DecompressionStream`으로 풀고 Native WebGL2로 렌더링한다. 외부 렌더링 라이브러리나 CDN 의존성은 없다.

`window.modelViewer.getState()`로 동 번호, 40세대 상태, 네 팔레트, 인쇄/물성 보기, 보이는 레이어 수, 카메라와 로딩 상태를 확인할 수 있다. `make3mf()`는 화면과 같은 기본·선택 레이어 및 동 명판만 3MF에 넣고 모든 삼각형에 0~3 재료 인덱스를 기록한다.

원래 창호 뒤의 빈 공간 때문에 생기는 분리된 내부 면 문제가 이전에 있었다. 구조 개구부를 먼저 만들고 창틀과 뒤판을 합쳐 해결했다. 이 부분을 변경하면 네 구성의 연결체 검증을 다시 확인한다.

이번 이관에서는 기하를 바꾸지 않았다. 프로젝트 밖 절대 경로를 제거한 미리보기 스크립트, 뷰어 빌드·검증 스크립트, 폴더 자동 생성 처리를 추가했다. 잘못된 첫 번째 모델과 디버그 메시, 실행 환경 전용 브라우저 스크립트는 포함하지 않았다. 이후 1단계 작업에서 시설물 이력과 출처를 문서화하고 검증 의존성 `networkx`를 선언했다.


## 2026-09-10 사진 기반 입면 업데이트

최신 사용자 사진 5장과 확대 관찰표를 기반으로 상층 주공 마크, 저층 동 번호, 대창 네 유형, 작은방 섀시 세 유형, 실외기 다섯 위치를 추가했다. `src/facade_variants.py`의 가중치·필드 규약을 뷰어에 함께 내장하며 seed/필드별 직접 지정 우선순위를 JSON·URL·완성/전개 3MF·STL에서 공유한다. 303·304동을 사진 확인 후보에 추가했다. 원래 4색 슬롯과 처음 전체 부착물 없음은 유지한다.
